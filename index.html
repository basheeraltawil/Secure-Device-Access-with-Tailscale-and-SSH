Professional Guide: Secure Device Access with Tailscale and SSH

A systematic approach to establishing encrypted, authenticated connections between devices using Tailscale's zero-trust network and SSH protocol.

Note: This guide covers both basic SSH over Tailscale and the enhanced security of Tailscale SSH, which uses WireGuard keys instead of traditional SSH key management:cite[2].

Understanding the Technology

Tailscale creates a secure virtual network (tailnet) where devices can communicate directly using the WireGuard® protocol:cite[10]. When combined with SSH, this provides:

  • End-to-end encryption via WireGuard in addition to SSH encryption:cite[2]
  • Automatic authentication using your Tailscale identity instead of SSH keys:cite[10]
  • Simplified access control through centralized policies rather than managing authorized_keys files:cite[2]
  • No need for bastion hosts or exposed SSH servers:cite[8]
Traditional SSH SSH with Tailscale Tailscale SSH
Manual SSH key management Manual SSH key management Automatic WireGuard key rotation:cite[2]
SSH server exposed to network SSH server accessible only via Tailscale IP:cite[8] Tailscale manages SSH authentication:cite[2]

Systematic Setup Guide

Follow these steps to establish secure SSH connections between your devices using Tailscale.

Install Tailscale on Both Devices

Begin by installing Tailscale on both the source (client) and destination (server) devices.

On Raspberry Pi (Linux):

# Download and install Tailscale
curl -fsSL https://tailscale.com/install.sh | sh

# Start Tailscale and connect to your network
sudo tailscale up

On macOS:

# Install via Homebrew (recommended)
brew install --cask tailscale

# Or download directly from tailscale.com
# Open the Tailscale app and sign in

When you run sudo tailscale up, you'll see an authentication URL. Open this in a browser and sign in with your identity provider (Google, GitHub, etc.) to authorize the device:cite[2].

Verify Device Connectivity

Ensure both devices are properly connected to your tailnet.

# Check Tailscale status and IP address
tailscale status
tailscale ip -4

Note the Tailscale IP address (format: 100.x.x.x) of the destination device. You'll use this for SSH connections.

If both devices show as online in tailscale status, they can communicate directly through the encrypted Tailscale network:cite[8].

Establish SSH Connection

Connect to the destination device using its Tailscale IP address.

# Basic SSH connection
ssh username@100.101.102.103

# Example for Raspberry Pi with default 'pi' user
ssh pi@100.101.102.103

If this is your first time connecting, you may encounter password authentication. For production environments, we recommend setting up SSH keys or enabling Tailscale SSH for enhanced security.

Enhanced Security: SSH Key Configuration

For more secure authentication, configure SSH keys instead of relying on passwords.

Generate SSH Key Pair (on client device):

# Generate a secure SSH key pair
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# Accept default location (~/.ssh/id_rsa)
# Set a strong passphrase for additional security

Copy Public Key to Server:

# Use ssh-copy-id for convenience
ssh-copy-id username@100.101.102.103

# Manual method if ssh-copy-id is unavailable:
cat ~/.ssh/id_rsa.pub | ssh username@100.101.102.103 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"

Advanced: Enable Tailscale SSH

For the highest level of security and manageability, enable Tailscale SSH on your destination device:cite[2].

# On the destination device (server)
tailscale up --ssh

Then configure SSH access rules in your Tailscale admin console:

// Example SSH access rule in Tailscale ACLs
{
  "ssh": [
    {
      "action": "accept",
      "src": ["user@example.com"],
      "dst": ["tag:servers"],
      "users": ["root", "autogroup:nonroot"]
    }
  ]
}

Tailscale SSH uses WireGuard keys for authentication instead of SSH keys, automatically handles key rotation, and provides centralized access control through your tailnet policy file:cite[2]:cite[10].

Security Best Practices

Implement these security measures to protect your SSH connections and infrastructure.

SSH Server Hardening

Edit /etc/ssh/sshd_config on your destination device:

# Disable password authentication (use keys only)
PasswordAuthentication no

# Disable root login directly
PermitRootLogin no

# Use a non-standard port (optional)
Port 2222

Tailscale Security Features

  • Use check mode for high-risk connections (e.g., root access) to require re-authentication:cite[2]
  • Implement access control rules to restrict SSH access to specific users and groups:cite[10]
  • Enable multi-factor authentication on your Tailscale account:cite[3]
  • Regularly review and update your tailnet access policies:cite[3]

Troubleshooting Common Issues

Problem Diagnosis Solution
Can't reach Tailscale IP Devices not in same tailnet or offline Run tailscale status on both devices; ensure both are using same account
Permission denied (publickey) SSH key not properly configured Verify ssh-copy-id completed successfully; check server authorized_keys file
Connection timeout SSH server not running or firewall blocking Ensure sshd is running; check sudo systemctl status ssh
Tailscale SSH not working SSH access rules missing or incorrect Verify SSH rules in Tailscale admin console; check tailscale set --ssh was run

Quick Command Reference

curl -fsSL https://tailscale.com/install.sh | sh  # Linux
