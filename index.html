Enterprise Note: This guide covers both traditional SSH over Tailscale and the enhanced security of Tailscale SSH, which uses WireGuard keys instead of traditional SSH key management for simplified operations.

Technology Overview

Tailscale creates a secure virtual network (tailnet) where devices communicate directly using the WireGuard® protocol. When combined with SSH, this enterprise-grade solution provides:

  • End-to-end encryption via WireGuard in addition to SSH encryption layers
  • Automatic authentication using your Tailscale identity provider instead of manual SSH key management
  • Centralized access control through policy-based rules rather than distributed authorized_keys files
  • Elimination of bastion hosts and exposed SSH servers through secure peer-to-peer tunnels
Traditional SSH SSH with Tailscale Tailscale SSH
Manual SSH key distribution & rotation Manual SSH key management Automatic WireGuard key rotation
SSH server exposed to network attacks SSH server accessible only via Tailscale IP Tailscale manages SSH authentication entirely
Complex bastion host architectures Direct peer-to-peer encrypted connections Direct connections with centralized ACL management

Implementation Guide

Follow these systematic steps to establish secure SSH connections between your devices using Tailscale.

Install and Enable SSH Server

Before establishing secure remote access, ensure the SSH server is properly installed and running on your target device (e.g., Raspberry Pi, Linux server).

Update Package Repository and Install OpenSSH Server:

# Refresh package lists to ensure latest versions
sudo apt update

# Install OpenSSH server package
sudo apt install openssh-server -y

Enable and Start SSH Service:

# Enable SSH service to start automatically on boot
sudo systemctl enable ssh

# Start SSH service immediately
sudo systemctl start ssh

Verify SSH Service Status:

# Confirm SSH service is running properly
sudo systemctl status ssh

Enterprise Best Practice: The sudo apt update command ensures your system has the latest package information before installation. Always verify service status with systemctl status to confirm successful deployment.

Install Tailscale on All Devices

Deploy Tailscale on both source (client) and destination (server) devices to establish your secure tailnet.

On Linux/Raspberry Pi:

# Download and execute Tailscale installation script
curl -fsSL https://tailscale.com/install.sh | sh

On macOS:

# Install via Homebrew (recommended for development environments)
brew install --cask tailscale

# Alternative: Download from tailscale.com
# Launch Tailscale application and authenticate

After installation, you'll need to authenticate your device with your Tailscale account using the commands in the next step.

Account Management: Connect to Tailscale

Authenticate your device with your Tailscale account to join the secure tailnet.

Log out of any existing account (if needed):

# If your device is already connected to another account:
sudo tailscale logout

Log in with your account:

# Connect device to your tailnet
sudo tailscale up

After running sudo tailscale up, you'll receive an authentication URL:

To authenticate, visit:
https://login.tailscale.com/a/xxxxxxx

Open this URL in a browser and sign in with your identity provider (Google, GitHub, Microsoft, etc.) to authorize the device.

Account Switching: The logout/login process is essential when transferring device ownership between accounts or organizations. This ensures clean authentication without conflicts.

Verify Tailscale Connectivity

Confirm all devices are properly connected to your tailnet and can communicate securely.

# Display tailnet device status and connectivity
tailscale status

# Retrieve Tailscale IPv4 address for this device
tailscale ip -4

Note the Tailscale IP address (format: 100.x.x.x) of your destination device for SSH connections.

Verification Complete: When both devices appear online in tailscale status, they can establish direct, encrypted communication through the Tailscale network without exposed network services.

Establish SSH Connection

Connect to the destination device using its Tailscale IP address for secure remote access.

# Standard SSH connection over Tailscale
ssh username@100.101.102.103

# Example for Raspberry Pi with default user
ssh pi@100.101.102.103

Security Notice: Initial connections may require password authentication. For production environments, immediately implement SSH keys or Tailscale SSH for enhanced security.

Enhanced Security: SSH Key Configuration

Implement SSH key-based authentication for passwordless, more secure access to your devices.

Generate SSH Key Pair (Client Device):

# Create a secure 4096-bit RSA key pair
ssh-keygen -t rsa -b 4096 -C "your_identifier@organization.com"

# Accept default file location (~/.ssh/id_rsa)
# Set a strong passphrase for additional security

Distribute Public Key to Server:

# Automated public key distribution
ssh-copy-id username@100.101.102.103

# Manual distribution method (if ssh-copy-id unavailable)
cat ~/.ssh/id_rsa.pub | ssh username@100.101.102.103 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"

Advanced: Enable Tailscale SSH

For maximum security and operational simplicity, implement Tailscale SSH which uses WireGuard keys instead of SSH keys.

# On the destination device (server)
tailscale up --ssh

Configure granular SSH access policies in your Tailscale admin console:

// Example enterprise SSH access policy
{
  "ssh": [
    {
      "action": "accept",
      "src": ["user@organization.com"],
      "dst": ["tag:production-servers"],
      "users": ["root", "autogroup:nonroot"]
    }
  ]
}

Enterprise Advantage: Tailscale SSH utilizes WireGuard keys for authentication, automatically handles cryptographic key rotation, and provides centralized access control through your tailnet policy file without manual key distribution.

Account Management Operations

Managing Tailscale Accounts on Devices

These operations are essential for device lifecycle management, ownership transfers, and troubleshooting authentication issues.

Check Current Account Status:

# Display current device authentication status
tailscale status --json | jq '.Self.UserID'

Logout from Current Account:

# Disconnect device from current tailnet
sudo tailscale logout

Login with New Account:

# Re-authenticate device with different account
sudo tailscale up

View Detailed Device Information:

# Comprehensive device status and configuration
tailscale status --verbose

Security Hardening & Best Practices

Implement these security measures to protect your SSH infrastructure and maintain compliance with security policies.

SSH Server Hardening

Edit /etc/ssh/sshd_config on your destination devices for enhanced security:

# Disable password authentication (keys only)
PasswordAuthentication no

# Restrict direct root login
PermitRootLogin no

# Implement non-standard port (defense in depth)
Port 2222

# Limit user access
AllowUsers deploy-user admin-user

# Reduce connection window
LoginGraceTime 60

Tailscale Security Features

  • Enable check mode for high-risk connections (e.g., root access) to require re-authentication
  • Implement granular access control rules to restrict SSH access based on user roles and device tags
  • Activate multi-factor authentication on your Tailscale account for additional security
  • Establish regular policy reviews to maintain least-privilege access principles
  • Utilize device approval workflows for operational control over new device connections

Troubleshooting & Diagnostics

Issue Root Cause Resolution
Cannot reach Tailscale IP Devices not in same tailnet or offline Execute tailscale status on both devices; verify account consistency
Permission denied (publickey) SSH key misconfiguration or missing Verify ssh-copy-id completion; inspect server authorized_keys file
Connection timeout SSH service not running or blocked Confirm sshd status with sudo systemctl status ssh; check firewall rules
Tailscale SSH failure SSH access policies missing or incorrect Validate SSH rules in Tailscale admin console; confirm tailscale up --ssh execution
Authentication URL not working Device already authenticated to different account Execute sudo tailscale logout then sudo tailscale up for clean authentication
